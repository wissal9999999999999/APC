 Mono/Multitâche


 Monotâche
    une seule tâche à la fois est exécutée par le système
         arrêt de la tâche : utilisateur/programme
         problème sur la tâche → plantage

 Multitâche
     plusieurs tâches exécutées en parallèle par le système
         arrêt de la tâche : utilisateur/programme/système
         problème sur une tâche → le système reprend la main

 2 familles de systèmes d’exploitation multitâche


 Coopératif (obsolète)
 Le système multitâche donne la main à une application qui décidera
 quand elle la rendra.
         si une tâche ne passe/rend pas la main → plantage
         risque d’iniquité du partage des ressources

 Préemptif
 Le système multitâche décide d’allouer du temps à chaque tâche et
 reprend la main une fois ce temps écoulé.
         quantum
         meilleure stabilité du système

 Ordonnanceur
 L’ordonnanceur sélectionne le prochain processus à exécuter
 ⇒ un processus en cours d’exécution est remplacée par un autre
 ⇒ politique d’ordonnancement (plus court temps d’exécution,
 tourniquet, . . .)

 Objectifs de la politique d’ordonnancement
     éviter les famines : processus sans temps d’exécution alloué
         gestion des priorités
         équité
         un temps de réponse acceptable : important pour les processus
         interactifs
         maximiser l’utilisation du processeur
         éviter le cache trashing : swap important de processus entre la
         mémoire et le disque

 Quelques algorithmes basiques


 Algorithme de type FIFO (Le plus simple)
 Le premier processus dans la file des prêts sera le premier exécuté.

 Plus court d’abord (Shortest Job First)
 Plusieurs processus de priorités équivalentes dans la file des processus
 prêts, le processus élu sera celui qui a la plus courte durée d’exécution
         nécessité d’évaluer la durée d’un processus
         nécessité de réorganiser la file
         risque de famine pour les processus les plus longs
         ⇒ augmentation de la priorité pour les processus en attente

 Algorithme du Tourniquet (Round Robin)
 Principe
      les processus sont placés dans une liste circulaire
         chaque processus dispose d’un quantum de temps pour s’exécuter
 Le quantum correspond au temps d’exécution donné à un processus.
         processus terminé durant le quantum
         ordonnanceur : passe la main au processus suivant
         processus non terminé durant le quantum :
         ordonnanceur : arrête le processus et passe la main au suivant

 Réglage du quantum
         quantum trop petit (notamment par rapport au temps de
         commutation)
         ⇒ le processeur passe sont temps à commuter
         quantum trop grand
         ⇒ le temps de réponse augmente

 Tourniquet avec gestion de priorités


 Priorité
 Certains processus peuvent être plus importants ou urgents
 ⇒ attribution de priorités aux processus

 Gestion des priorités
      plusieurs files d’attente selon les priorités
         chaque file est gérée par l’algorithme du tourniquet
         éviter une famine des processus moins prioritaire
         ⇒ diminution régulière de la priorité du processus élu
         ⇒ commutation vers le processus le plus prioritaire
         ⇒ insertion de l’ancien processus élu dans sa nouvelle file de priorité

 #include <stdio.h>
 #include <stdlib.h>
 #include <unistd.h>
 #include <sys/wait.h>

 void main(void) {
   pid_t pid ;
   pid = fork() ;
   switch (pid) {
     case -1:
       printf("erreur␣:␣echec␣du␣fork()\n");
       exit(1);
       break ;
     case 0:
       printf("--␣Processus␣fils␣:␣pid␣=%d\n", getpid() );
       sleep(10);
       printf("--␣fin␣du␣fils␣\n");
       exit(0);
       break ;
     default:
       printf("Processus␣pere␣:␣le␣fils␣a␣un␣pid=%d\n", pid) ;
       wait(NULL);
       printf("Fin␣du␣pere\n");
     }
 }

         suspend le processus appelant jusqu’à la fin d’un de ses fils

         tubes nommés (FIFOs)
         tubes anonymes (entre processus parents/enfants)
         mémoire partagée

 Tubes (Pipes)

 Définition
       mécanisme de communication unidirectionnel
         un processus écrit dans le tube, l’autre lit dans le tube
         les données sont lues dans l’ordre où elles ont été écrites
         la lecture est destructrice
         la lecture et l’écriture sont bloquantes par défaut

 Manipulation des tubes
     tube anonyme : int pipe(int pipefd[2])
     crée un tube anonyme, pipefd[0] pour lire, pipefd[1] pour écrire
         tube nommé : int mkfifo(const char *pathname, mode t
         mode)
         crée un tube nommé dans le système de fichiers

 Sémaphores
 Définition
       mécanisme de synchronisation entre processus
         les opérations sur un sémaphore sont atomiques

 Opérations de base
 Un sémaphore S est un entier non signé.
         P(S)
                si S > 0, alors S ← S - 1
                si S = 0, le processus est bloqué jusqu’à ce que S > 0
         V(S)
                S←S+1
                si des processus sont bloqués sur P(S), l’un d’eux est réveillé
         Z(S)
                si S = 0, le processus continue
                si S > 0, le processus est bloqué jusqu’à ce que S = 0
