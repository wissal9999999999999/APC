Les collections
Définition
Elles permettent de gérer des groupes d’objets de même type, leur
nombre n’est pas forcément connu à l’avance.

Collection versus tableau
Tableaux :
    non redimensionnables
    l’insertion nécessite un décalage
    les indices doivent être des entiers
    légers en mémoire et accès en O(1)
Collections :
    choix de l’implémentation (complexité) et de l’interface
    structures dynamiques
    algorithmes communs
    plus gourmands en mémoire

L’interface Collection
Description de l’interface
   public interface Collection<E> extends Iterable<E> {
     // Operations de base
     int size();
     boolean isEmpty();
     boolean contains(Object element);
     boolean add(E element); // Optional si non implémenté => UnsupportedOperationException
     boolean remove(Object element);            // Optional
     Iterator<E> iterator();

       // Operations de masse (bulk operation)
       boolean containsAll(Collection<?> c);
       boolean addAll(Collection<? extends E> c); // Optional
       boolean removeAll(Collection<?> c);       // Optional
       boolean retainAll(Collection<?> c);       // Optional
       void clear();                             // Optional

       // Opérations de conversion vers des tableaux
       Object[] toArray();
       <T>T[] toArray(T[] a);
   }
                                                                                                 issu du “tutoriel Sun”


Cette interface est commune à toute collection et permet ainsi une
interopérabilité totale.

L’interface Map
Description de l’interface
   public interface Map<K,V> {
     // Opérations de base
     V put(K key, V value);
     V get(Object key);
     V remove(Object key);

       boolean equals(Object o);
       int hashCode();
       K getKey();
       V getValue();
       V setValue(V value);
     }
   }

Le pattern Itérateur : l’interface Iterator

Principe
Le pattern itérateur est utilisé afin de parcourir une collection quelque
soit son implantation et quelques soient les éléments qu’elle contient.

L’interface d’Iterator
    public interface Iterator<E> {
      boolean hasNext();
      E next();
      void remove(); // Optional
    }



L’interface Enumeration
Il est maintenant déconseillé d’utiliser cette interface pour itérer sur des
collections. En effet, pendant une itération, l’intégrité de la collection
n’est pas assurée si il y a retrait d’un élément.

package fr.insarouen.iti.prog.cours5;
import java.util.*;

public class ExempleCollections {
  public static void main(String[] args) {
    ArrayList al=new ArrayList();
    al.add(Integer.valueOf(101));
    al.add(Integer.valueOf(504));
    al.add(Integer.valueOf(121));
    al.add(Integer.valueOf(101));
    System.out.println(al);
    // le ListIterator fournit des fcts supplementaires (previous, hasPrevious, ...)
    for (ListIterator li=al.listIterator(); li.hasNext();)
      System.out.println(String.format("--␣%d␣--",((Integer)li.next()).intValue()/2));
    for (Object i : al)
      System.out.println(String.format("--␣%d␣--",((Integer)i).intValue()/2));

     HashSet hs=new HashSet(al);
     System.out.println(hs);
     for (Iterator i=hs.iterator();i.hasNext();) {
       String eltCourant=i.next().toString();
       if (eltCourant.startsWith("1"))
          i.remove();
     }
     System.out.println(String.format("*%s*",hs));
 }

Le for/in

Syntaxe
      for(declaration : expression)
        instruction ou bloc d’instructions


Utilisation
Cette nouvelle boucle permet d’itérer à l’aide de variables de types
simples ou objets sur des tableaux ou des collections.

   for (Object i : al)

   for (Iterator i=hs.iterator();i.hasNext();) {
     String eltCourant=i.next().toString();
     if (eltCourant.startsWith("1"))
        i.remove();                // impossible avec le for/in
   }

Principe du type générique
Un type générique est un type paramètrable par un type.
Dans la grande majorité des cas, il s’agit de paramétrer des collections
par la déclaration du type qu’elles manipuleront.

Syntaxe
   Type<parametre1, ..., parametreN> // où parametre est un type

Conversion de types génériques


Attention !!!
La conversion de type ne se fait que sur le type de base et non sur le type
paramètre.

Illustration du problème
     List<String> lstr = new LinkedList<String>(); //ok
     List<Object> lobj = lstr; // ne compile pas

     // sinon on aurait le problème suivant
     lobj.add(new Object());
     String str = lstr.get(0); // assignation d’un Object à un String

public class Paire<G,D> {
  private G valeurGauche;
  private D valeurDroite;
  public Paire(G valeurGauche, D valeurDroite) {
    this .valeurGauche=valeurGauche;
    this .valeurDroite=valeurDroite;
  }
  public G getValeurGauche() {
    return valeurGauche;
  }
  public D getValeurDroite() {
    return valeurDroite;
  }
  public void setValeurGauche(G valeur) {
    valeurGauche = valeur;
  }
  public void setValeurDroite(D valeur) {
    valeurDroite = valeur;
  }
  public String toString() {
    return String.format("(%s,%s)",getValeurGauche(),getValeurDroite());
    // %s pour appel au toString() sinon pb de type d^
                                                     u à la généricité
  }
}

Le joker : ?

Objectif
Spécifier que n’importe quel type de paramètre est accepté.
Collection<?> est une collection d’inconnus

Exemple
 public void afficheCollection(Collection<?> c) {
   for (Iterator i<?>=c.iterator(); i.hasNext();)
     System.out.println(i.next().toString());
   }
 }


Remarque
L’utilisation de Collection<Object> est une faute puisque la conversion
est sur le type de base et non sur le type paramètre. La classe “mère” de
toutes les collections est Collection<?> et non Collection<Object>.

Manipulation des ?
Le type des objets manipulés est inconnu
     Collection<?> c = new ArrayList<String>();
     c.add(new Object());      // ne compile pas
     c.add(new String(‘‘tutu’’)); // ne compile pas
     Object obj = c.get(0); // compile

    on ne peut donc pas ajouter d’élément, puisque le type est inconnu
    par contre on peut consulter sans problème via Object, puisqu’on
    est au moins sûr de ce type.
